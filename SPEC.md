# ФЛЮКС-1: Полная спецификация проекта
## (Однобитный потоковый компьютер с тремя звуковыми каналами)

---

## 1. Философия проекта

**Девиз:** *«256 бит данных. Бесконечность кода. Всё, что нужно для счастья.»*

**Цель:** Создать эмулятор вычислительной машины с минималистичной архитектурой, которая:
- Работает на любом железе (включая Intel 8086).
- Имеет визуальную матрицу 16×16 для отображения состояния.
- Генерирует звук через три квадратных канала с неограниченной модуляцией.
- Станет платформой для творчества, обучения и соревнований (Bad Apple, игры, чиптюн).

**Аудитория:** Программисты, ретро-энтузиасты, музыканты, студенты.

## 2. Архитектура

### 2.1. Память

| Тип | Размер | Назначение | Адресация |
|-----|--------|------------|-----------|
| **GRID (ОЗУ данных)** | 256 бит (32 байта) | Хранение состояния битов, переменных, экранной матрицы | 0x00..0xFF (8 бит) |
| **ROM (ПЗУ программ)** | до 64 КБ | Инструкции, константы, сжатые данные (кадры, таблицы) | Program Counter (16 бит) |

**Примечание:** GRID физически — это массив из 32 байт, где каждый бит соответствует ячейке (x, y) = (addr % 16, addr / 16). ROM — линейное адресное пространство, загружаемое из файла прошивки.

### 2.2. Регистры процессора

| Регистр | Разрядность | Описание |
|---------|-------------|----------|
| PC | 16 бит | Program Counter (указывает на текущую инструкцию в ROM) |
| ACC | 1 бит | Аккумулятор (результат операций) |
| CARRY | 1 бит | Флаг переноса/заёма (для арифметики) |
| MODE | 2 бита | Режим работы (обычный, звуковой, ввод-вывод) |

### 2.3. Система команд (ASM-Флюкс)

Каждая инструкция — 8 бит.  
Биты 7-6: код операции (OpCode).  
Биты 5-0: аргумент (6 бит) — адрес ячейки GRID или данные.

| OpCode (бинарный) | Мнемоника | Описание | Пример |
|-------------------|-----------|----------|--------|
| `00` | **NOP** | Нет операции | `NOP` |
| `01` | **SET** | Установить бит по адресу в 1 | `SET 0x0A` |
| `10` | **CLR** | Очистить бит по адресу в 0 | `CLR 0x0F` |
| `11` | **JMP** | Безусловный прыжок на адрес в ROM (аргумент — младшие 6 бит адреса, PC = (PC & 0xFFC0) \| arg) | `JMP 0x10` |

**Дополнительные псевдо-инструкции (реализуются через комбинации):**
- `GET addr` — прочитать бит в ACC.
- `PUT addr` — записать ACC в бит.
- `XOR addr` — ACC ^= GRID[addr].
- `JZ addr` — прыжок, если ACC == 0.

Но для простоты оставляем только 4 базовые команды. Остальное — эмуляция через макросы или код.

**Расширение:** Если нужно больше команд, можно ввести двухбайтовые инструкции (первый байт — опкод, второй — аргумент), тогда адресное пространство ROM не ограничено 64 КБ.

## 3. Звуковой движок (3 канала)

### 3.1. Аппаратная часть (виртуальная)

Каждый канал имеет:

- **Частота (16 бит)** — значение от 0 до 65535 (нота).
- **Ширина импульса (8 бит)** — скважность (0..255, где 128 = 50%).
- **Громкость (8 бит)** — 0..255 (линейная).
- **Источник модуляции (8 бит)** — адрес ячейки GRID или номер канала (0,1,2) или внешний сигнал.
- **Глубина модуляции (16 бит, знаковое с фиксированной точкой 8.8)** — коэффициент модуляции.

**Режим работы:** Каждый канал генерирует прямоугольный сигнал с заданными параметрами. Если частота = 0 — канал выключен.

### 3.2. Модуляция

Каждый канал может модулировать любой параметр **другого канала** (или самого себя) в реальном времени.

**Карта модуляции:**
- Источник: бит из GRID (0/1) или выход канала (0..255, значение амплитуды).
- Цель: частота, ширина импульса, громкость другого канала.
- Алгоритм: `цель = цель_базовая + (источник * глубина)`.

**Пример:** Канал 1 модулирует частоту канала 2 битом из ячейки 0x0A. Когда бит = 1, частота канала 2 увеличивается на 100 Гц.

### 3.3. Выходной буфер

Звук генерируется в виде 16-битных семплов (моно или стерео) с частотой дискретизации 44100 Гц (или 22050 для 8086). Буфер передаётся в аудио-устройство (SDL2, PC Speaker, etc).

## 4. Программная модель

### 4.1. Структура эмулятора (C++/C)

```cpp
// flux_core.h
#pragma once
#include <cstdint>
#include <array>

class FluxCPU {
public:
    static constexpr size_t GRID_BYTES = 32;      // 256 бит
    static constexpr size_t ROM_SIZE = 65536;     // 64 КБ
    static constexpr int AUDIO_CHANNELS = 3;

    // Состояние
    std::array<uint8_t, GRID_BYTES> grid;    // данные
    std::array<uint8_t, ROM_SIZE> rom;       // программа
    uint16_t pc = 0;
    uint8_t acc = 0;
    bool carry = false;

    // Звук
    struct Channel {
        uint16_t freq = 0;
        uint8_t duty = 128;
        uint8_t volume = 0;
        uint8_t mod_src = 0;   // адрес бита или канал (0..2) или 0xFF = off
        int16_t mod_depth = 0; // 8.8 fixed point
        float phase = 0.0f;
        float sample() const;  // генерирует один семпл
    };
    std::array<Channel, AUDIO_CHANNELS> ch;

    // Методы
    void tick();          // один такт процессора (чтение и исполнение)
    void render_grid();   // вывод матрицы в консоль/окно
    void audio_callback(float* out, int frames); // заполнение буфера
};
```

### 4.2. Цикл эмуляции

```cpp
void FluxCPU::tick() {
    uint8_t instr = rom[pc++];
    uint8_t op = (instr >> 6) & 0x03;
    uint8_t arg = instr & 0x3F; // 6-битный аргумент

    switch (op) {
        case 0: // NOP
            break;
        case 1: // SET
            grid[arg >> 3] |= (1 << (arg & 7));
            break;
        case 2: // CLR
            grid[arg >> 3] &= ~(1 << (arg & 7));
            break;
        case 3: // JMP
            pc = (pc & 0xFFC0) | (arg & 0x3F);
            break;
    }

    // Обновление звука (вызов audio_callback не здесь, а отдельно)
}
```

## 5. Визуализация

### 5.1. Режимы отображения

- **Консольный ASCII:** 16 строк по 16 символов (`█` или `░`), обновление каждые N тактов.
- **Графический (SDL2):** окно 512x512 пикселей, каждый бит = 32x32 пикселя. Цвет: зелёный для 1, тёмный для 0.
- **Тепловая карта:** цвет зависит от частоты изменения бита (от синего к красному).

### 5.2. Управление мышью

Клик по ячейке переключает её состояние (интерактивный режим) — полезно для отладки и живых выступлений.

## 6. Загрузка прошивок

Прошивка — бинарный файл, содержащий образ ROM (первые 64 КБ). Формат: просто raw-байты.  
Ассемблер (ASM-Флюкс) — текстовый файл, транслируемый в бинарник с помощью утилиты `asmflux` (написать на Python или C++).

**Пример прошивки (бегущий огонёк):**

```
; loop.asm
START:
    SET 0x00
    CLR 0x01
    JMP START
```

**Команда сборки:** `asmflux loop.asm -o loop.flux`

## 7. Звуковой движок: детали реализации

### 7.1. Генерация семпла канала

```cpp
float FluxCPU::Channel::sample() {
    if (freq == 0 || volume == 0) return 0.0f;
    float t = phase / 65536.0f; // 0..1
    float val = (t < (duty / 255.0f)) ? 1.0f : -1.0f;
    phase += freq * 2.0f * 3.14159265f / 44100.0f;
    if (phase >= 65536.0f) phase -= 65536.0f;
    return val * (volume / 255.0f);
}
```

### 7.2. Модуляция (вызывается перед генерацией каждого семпла)

```cpp
void apply_modulation(FluxCPU::Channel& src, FluxCPU::Channel& dst, float depth) {
    float mod_val = (src.volume / 255.0f); // или бит из GRID
    dst.freq += (int16_t)(mod_val * depth * 256.0f);
    // аналогично для duty и volume
}
```

### 7.3. Микширование

Три канала суммируются и клиппятся к диапазону [-1.0, 1.0].

## 8. Портирование на 8086 (DOS)

### 8.1. Ограничения

- Только текстовый режим (или CGA 320x200).
- Звук через PC Speaker (PIT таймер) — только один канал, частота переключения.
- Память: модель `tiny` (всё в одном сегменте).

### 8.2. Адаптация

- Визуализация: ASCII-графика (символы 219 и 176).
- Звук: каждый такт эмуляции переключает динамик на основе суммы трёх каналов (ШИМ-аппроксимация).
- Управление: стрелки + пробел для переключения битов.

### 8.3. Сборка

```bash
# Для DOS (Turbo C)
tcc -mt -O -G -o flux.exe flux_dos.c

# Для современного (SDL2)
g++ -std=c++17 -o flux flux.cpp -lSDL2 -lm
```

## 9. Бенчмарки и вызовы

### 9.1. Bad Apple Challenge

**Задача:** Запустить анимацию Bad Apple на Флюкс-1 в реальном времени (30 кадров/сек) с использованием только 256 бит GRID и до 64 КБ ROM.

**Решение:**
- Конвертировать видео в последовательность кадров 16×16 бит.
- Сжать RLE (разность кадров) или хранить ключевые кадры + интерполяцию.
- Прошивка должна читать данные из ROM и обновлять GRID каждый кадр.

**Требование:** Общее время выполнения не должно превышать 5 минут при эмуляции на 8086 (4.77 МГц).

### 9.2. Игровой челлендж

**Змейка:** Реализовать игру "Змейка" на ассемблере Флюкс-1. Управление — клавиши WASD. Максимальная длина — 16 сегментов.

**Тетрис:** Поле 8×16, фигуры — 3 бита. Оценка количества строк.

### 9.3. Музыкальный челлендж

Написать прошивку, которая генерирует мелодию (например, "Popcorn" или "Tetris Theme") через три канала с модуляцией. Выложить аудио-демку в репозиторий.
