# ФЛЮКС-1

Однобитный компьютер: GRID на 256 бит — и память, и экран; прошивка 64 КБ;
1-битный аккумулятор; три квадратных канала как периферия.

ФЛЮКС-1 — это машина фон Неймана: состояние — GRID на 256 бит (32 байта ОЗУ),
программа — ПЗУ до 64 КБ («прошивка»), регистры — PC (16 бит), ACC (1 бит),
CARRY (1 бит) и MODE (2 бита). Каждая инструкция занимает всего 8 бит: четырёх
базовых опкодов NOP/SET/CLR/JMP достаточно, а двухбайтовый слой расширений
добавляет чтение/запись битов и ветвления.

Главная идея: GRID — это одновременно и экран, и память. Дисплей 16×16 рисует
GRID напрямую. Аппаратной арифметики нет: это 1-битный CPU, и вся логика
(счётчики, сумматоры, автоматы) строится из XOR и условных прыжков. Три
квадратных канала — просто ещё одно устройство, которым правит прошивка
(с FM/модуляцией между каналами).

```
                 GRID на 256 бит (экран + ОЗУ)
                 ┌───────────────────────┐
   ROM 64КБ ──►  │  CPU (PC, ACC, CARRY) │ ──► экран 16×16
   (прошивка)    └───────────────────────┘ ──► 3 квадратных канала
```

## Быстрый старт

```
g++ -O2 -std=c++17 asm/asmflux.cpp -o asm/asmflux.exe     # ассемблер
g++ -O2 -std=c++17 flux.cpp flux_core.cpp -o flux.exe      # эмулятор

asmflux firmware/loop.asm -o firmware/loop.flux            # собрать прошивку
flux firmware/loop.flux --tps 4                            # смотреть
flux firmware/counter.flux --tps 30                        # двоичный счётчик
flux firmware/adder.flux --grid-hex --steps 300            # программный сумматор
flux firmware/music.flux --wav firmware/music.wav --secs 12 # звук в WAV
```

Новичок? Читайте **[docs/PROGRAMMING.ru.md](docs/PROGRAMMING.ru.md)** (EN:
[PROGRAMMING.md](docs/PROGRAMMING.md)) — гайд с аппаратным уклоном.

### Демо-прошивки

| Файл                  | Что делает                                                        |
|-----------------------|-------------------------------------------------------------------|
| `firmware/loop.asm`   | Бегущий огонёк: SET бит, CLR бит, JMP. Минимальная программа.     |
| `firmware/counter.asm`| 8-битный двоичный счётчик из триггеров (XOR + вечная единица) с программным ripple-переносом — GRID и есть регистр. |
| `firmware/adder.asm`  | Программный полный сумматор с ripple-переносом: складывает два 4-битных числа в битах GRID, результат (5 бит) пишет обратно в GRID. Чистая логика, бит за битом. |
| `firmware/beep.asm`   | Трёхканальный аккорд (C-dur) — звук это лишь одна из периферий.  |
| `firmware/music.asm`  | Мелодия из 4 аккордов (C–Am–F–G): 2-битный счётчик в GRID, канал 2 — LFO 6 Гц, FM-модулирует ch0, флаг бита тумблирует громкость ch1. |

```
flux firmware/counter.flux --tps 30 --acc        # смотрим двоичный счётчик
flux firmware/adder.flux --grid-hex --steps 200  # A=5 + B=3 -> S=8
flux firmware/beep.flux --wav firmware/beep.wav --secs 12
```

## Набор инструкций

Каждая инструкция — один байт:

| биты 7..6 | мнемоника | значение                                     |
|-----------|-----------|-----------------------------------------------|
| `00`      | `NOP`     | нет операции                                  |
| `01`      | `SET a`   | grid[a] = 1                                   |
| `10`      | `CLR a`   | grid[a] = 0                                   |
| `11`      | `JMP a`   | PC = (PC & 0xFFC0) \| a  (прыжок в пределах 64-байтного блока) |

Ассемблер никогда не эмитит байт `0xFC` как базовую инструкцию, поэтому он
безопасен как *префикс расширений*: `0xFC <sub> <операнды>`. Псевдоинструкции:

| мнемоника | кодировка       | значение                                   |
|-----------|-----------------|--------------------------------------------|
| `GET a`   | `FC 00 a`       | ACC = grid[a]                              |
| `PUT a`   | `FC 01 a`       | grid[a] = ACC                              |
| `XOR a`   | `FC 02 a`       | ACC = ACC XOR grid[a] (инверсия)           |
| `JZ a`    | `FC 03 a`       | если ACC==0 — прыжок в пределах блока      |
| `JMPF a`  | `FC 05 aL aH`   | PC = a (полный 16-битный прыжок)           |
| `JZF a`   | `FC 06 aL aH`   | если ACC==0 — PC = a                       |
| `COPY d s`| `FC 07 d sL sH` | байт GRID[d] = ROM[s]                      |
| `SETCH c p v` | `FC 04 c p vL vH` | параметр канала (см. ниже)             |

### Управление звуком (`SETCH c p v`)

| p | параметр   | значение                                          |
|---|------------|----------------------------------------------------|
| 0 | `freq`     | частота в Гц (16 бит)                              |
| 1 | `duty`     | скважность 0..255 (0 = тишина, 255 = постоянка)    |
| 2 | `volume`   | 0..255                                             |
| 3 | `mod_src`  | 0x00..0xFF бит GRID, 0xF0..0xF2 канал, 0xFF выкл   |
| 4 | `mod_depth`| 8.8 с фикс. точкой (256 = 1.0)                     |
| 5 | `mod_dest` | 0 = freq, 1 = duty, 2 = volume                     |

Синтаксический сахар ассемблера:

```
FREQ ch v     ; SETCH c 0 v
DUTY ch v     ; SETCH c 1 v
VOL  ch v     ; SETCH c 2 v
MOD  ch src depth dest   ; SETCH c 3 src, SETCH c 4 depth, SETCH c 5 dest
```

Модуляция: `target = base + source * depth`, где source — бит GRID или выход
(+1/−1) другого канала. Так `MOD 0 0xF2 200 0` заставляет частоту канала 0
покачиваться на ±200/256, когда канал 2 высокий, — вибрато/FM.

## Директивы ассемблера

```
.org 0x100         ; продолжить с адреса
.byte 1, 2, 0x0F   ; эмитить байты
.word 0x1234, ...  ; эмитить 16-битные слова (LE)
.incbin "file"     ; включить сырые байты
LABEL:             ; метка
; или #            ; комментарий
```

Метки поддерживают арифметику: `JMPF FRAME_TABLE+32`, `COPY 3 TABLE+1`.

## Параметры эмулятора

```
flux rom.flux [--tps N] [--frames N] [--wav out.wav] [--wav-rate HZ]
             [--secs S] [--headless] [--acc] [--grid-hex] [--steps N]
```

* `--tps N`    тактов CPU в секунду для анимации (по умолчанию 60)
* `--wav out.wav` записать звук в WAV и выйти (`--secs` задаёт длину)
* `--wav-rate HZ` частота дискретизации (по умолчанию 44100; 22050 — для 8086)
* `--acc`      печатать также регистры каналов (freq/duty/vol/mod)
* `--grid-hex` печатать все 32 байта GRID как hex (вид логического анализатора)
* `--steps N`  выполнить N инструкций и показать один кадр (для тестов)

## Особенности реализации

* GRID — 256 бит = 32 байта. Бит `y*16+x` рисуется в строке y, столбце x.
* GRID — и состояние программы: «вечная единица» (например `SET 0x0F`) плюс
  `XOR` дают триггер; два таких бита — 2-битный счётчик.
* Лимит 64 байта на `JMP`/`JZ` — осознанное ограничение, заставляющее делать
  самодостаточные блоки; `JMPF`/`JZF` снимают его для больших программ.
* Звук: 16-битный фазовый аккумулятор на канал, wrap на 65536; сэмпл = ±1 с
  шагом скважности; суммируется и ограничивается до 16-битного PCM. WAV — mono.
