# Архитектура Flux-1

В этом документе описан модель выполнения Flux-1: клетка, волна, синхронный
такт, коллизии и звуковой конвейер. Язык описан в [LANGUAGE.ru.md](LANGUAGE.ru.md).

---

## 1. Машина

Flux-1 — это **массово-параллельная 1-битная вычислительная машина в
пространстве**. Это не фон-неймановский CPU с регистрами и потоком инструкций.
Это сетка 16×16 **клеток**, каждая из которых одновременно элемент памяти,
крошечное АЛУ и маршрутизатор. Вычисления происходят *там, где находятся
волны*.

| Константа | Значение | Смысл                  |
|-----------|----------|------------------------|
| `kGrid`   | 16       | грань сетки (256 клеток)|
| `kMaxDelay` | 15    | максимум задержки пути |
| `kChans`  | 3        | квадратные каналы звука|

---

## 2. Клетка

```cpp
struct Cell {
    uint8_t bit : 1;   // бит данных (присутствие волны)
    uint8_t acc : 1;   // бит аккумулятора (постоянный флаг)
    uint8_t delay;     // отложенная задержка пути (такты)
    Dir     dir;       // направление, куда клетка сейчас толкает бит
};
```

* **`bit`** — занята ли клетка волной в этот такт.
* **`acc`** — постоянный 1-битный регистр. Он *не* очищается между тактами;
  переживает `memset` через снимок/восстановление в фазе B. Это постоянная
  память Flux-1. Следы, гейты, флаги — всё на `acc`.
* **`delay`** — оставшееся время зарядки текущего бита (§4).
* **`dir`** — текущее направление маршрутизации клетки, используется в `send H`.

Клетке также принадлежит **программа**: упорядоченный список `Rule`
(см. LANGUAGE.ru.md §8).

---

## 3. Волна

Волна — бит в пути. Концептуально это кортеж `(x, y, dir, bit, delay)`.
Когда правило толкает бит соседу, планируется `Move` с координатами цели и
**задержкой**; волна «летит» `delay` тактов до приземления.

Задержки — инструмент программиста для работы со временем: `send E 2`
означает, что бит достигнет восточного соседа через 2 такта. Две волны с
разными задержками могут прийти в разное время, даже если отправлены в один
такт.

---

## 4. Синхронный такт

Flux-1 использует строгую **двухфазную** модель, как настоящая синхронная
цифровая схема. Все чтения — в фазе A, все записи фиксируются в фазе B.

### Фаза A — вычисление

Для каждой клетки `(x, y)`:

```
if (!cell.bit и у клетки нет правил) skip
hadBit = cell.bit

if (cell.bit && cell.delay > 0):
    cell.delay--              # зарядка
    stay.append((idx, cell.delay))
    continue

consumed = false
for rule r in cell.rules (по порядку):
    if !condOk(r.cond, cell.bit, cell.acc): continue
    switch r.action:
        Send:   # только когда cell.bit
                цель = сосед в (r.dir или cell.dir)
                если в сетке: moves.append(цель, bit, r.delay)
                consumed = true
        Emit:   # генератор: выдаёт 1 соседу
                moves.append(цель, 1, r.delay)
                # НЕ consumed — продолжает излучать
        Stop:   consumed = true
        SetAcc/ClearAcc/ToggleAcc: меняют cell.acc
        ChanFreq/ChanAmp/ChanPhase/ChanMod: меняют звуковой канал
    if consumed: break

if (!consumed && hadBit):
    stay.append((idx, 0))     # зависшая волна
```

Ключевые моменты:

* **Побеждает первое совпадение.** Правила просматриваются по порядку; первое
  *потребляющее* совпадение останавливает просмотр. Непотребляющие действия
  (операции acc, звук) выполняются, и просмотр продолжается.
* **Правила срабатывают только на готовый бит** — заряжающаяся волна
  правил не запускает.
* **`emit` никогда не потребляет**, поэтому излучатели работают постоянно.
* **`send` за границу убивает волну** (цель не планируется).

### Фаза B — фиксация

```
accSnap[i] = grid[i].acc                  # сохранить аккумуляторы
memset(grid, 0)                           # очистить всё
grid[i].acc = accSnap[i]                  # восстановить аккумуляторы

for (idx, d) in stay:   grid[idx].bit = 1; grid[idx].delay = d
for m in moves:         if grid[m.idx].bit: continue   # коллизия!
                        grid[m.idx].bit = 1
                        grid[m.idx].delay = m.delay
```

* Все изменения состояния фиксируются **одновременно**. Клетка может быть
  прочитана правилом соседа и при этом сама отправить волну в том же такте —
  это независимые операции.
* **Аккумуляторы сохраняются** через такт (снимок/восстановление).

## 5. Коллизии

Когда в один такт на одну клетку приземляются две или более `Move`,
**побеждает первая** (порядок обхода: строки, затем столбцы, порядок
источников). Более поздние отбрасываются. На практике хорошо составленные
программы дают каждой клетке одно правило и полагаются на разнесение задержек,
поэтому коллизии редки; когда случаются — работают как примитив
*слияние/поглощение*.

---

## 6. Тайминг

Волна с `send DIR D`:

1. такт T — правило срабатывает, `Move` планируется для соседа.
2. такты T+1 … T+D — волна **заряжается** в точке назначения
   (`delay` отсчитывается вниз; рисуется `o`).
3. такт T+D+1 — волна действует в точке назначения
   (`delay == 0`; рисуется `#`).

То есть задержка 2 — примерно 3 такта на прыжок, а путь в 16 клеток при
`send E 2` занимает около 48 тактов. `emit` с задержкой 0 кладёт бит на один
такт позже, давая поезд импульсов.

`inject ... D` ведёт себя так же: впрыснутая волна действует через `D+1`
тактов после впрыскивания.

## 7. Звуковой конвейер

Звук рендерится **синхронно** с тактами сетки. Каждый такт даёт `sps`
сэмплов (по умолчанию `44100/60`). Действия `freq`/`amp`/`phase`/`mod`
вступают в силу на *начале* следующего блока сэмплов.

### Квадратный осциллятор

Каждый канал `c` — фазовый аккумулятор:

```
dt   = sps / rate
twopi = 2π
for s in 0..sps-1:
    inst = c.freq
    if c.modSrc >= 0: inst += c.modDepth * channels[c.modSrc].last
    c.phase += inst * twopi * dt
    c.last  = c.amp * (sin(c.phase) >= 0 ? +1 : -1)
    mix += c.last
audio.push(mix)
```

* `inst` — мгновенная частота; FM-член сдвигает её на
  `modDepth * сэмпл(модулятора)`.
* Квадрат берётся по знаку `sin(phase)`, давая бинарную форму сигнала.
* `last` — сигнал модулятора, поэтому порядок каналов в маршруте `mod J D`
  важен для звуковых FM-стеков.

### Вывод WAV

`--wav` записывает монофонический 16-битный PCM-файл с частотой `rate` Гц.
Сэмплы жёстко ограничиваются `[-1, 1]` перед преобразованием.
Длительность = `ticks * sps / rate` секунд.

## 8. Рендер

ASCII-рендер показывает один кадр сетки:

| Символ | Условие                              |
|--------|--------------------------------------|
| `.`    | `!bit && !acc`                       |
| `#`    | `bit && delay == 0`                  |
| `o`    | `bit && delay > 0`                   |
| `A`    | `!bit && acc` (только с `--acc`)     |

Нижний колонтитул `tick=N  waves=K` сообщает такт и число живых волн
(пересчитывается в конце каждой фазы B).
