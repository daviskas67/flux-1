# Архитектура ФЛЮКС-1

ФЛЮКС-1 — крошечный компьютер фон Неймана, чья единственная память является
экраном, а три квадратных канала превращают эту память в звук.

## Модель машины

```
        ┌──────────────────────────────────────────────┐
        │              CPU ФЛЮКС-1                      │
        │   PC ──16 бит──► адрес                        │
        │   │                                           │
        │   ▼                                           │
        │  ROM (64 КБ, прошивка, только чтение) ──декод─►┼──► запись в GRID
        │                                               │
        │   GRID: 256 бит = 32 байта ОЗУ                │
        │   ACC: 1 бит    CARRY: 1 бит   MODE: 2 бита   │
        └──────────────────────────────────────────────┘
              │ биты GRID                     │ параметры каналов
              ▼                               ▼
        16×16 дисплей (ASCII/SDL)      3 квадратных канала
                                         фазовые аккумуляторы
                                         FM / PWM / тремоло
                                              │
                                              ▼
                                         микшер → WAV / звук
```

## Состояние

| регистр  | разряд | значение                                      |
|----------|--------|------------------------------------------------|
| `grid`   | 256 б  | ОЗУ + экран: бит `y*16+x` = пиксель (x,y)      |
| `rom`    | 64 КБ  | прошивка, только чтение                        |
| `pc`     | 16 б   | счётчик команд                                 |
| `acc`    | 1 б    | аккумулятор (GET/PUT/XOR/JZ/JZF)               |
| `carry`  | 1 б    | резерв для арифметических расширений           |
| `mode`   | 2 б    | резерв для переключения режимов                |
| `ch[3]`  | —      | звуковые каналы (см. Звук)                     |

## Модель исполнения

CPU выбирает один байт из `rom[pc]`, исполняет его, затем увеличивает `pc`
(кроме прыжков). Каждая инструкция занимает минимум 1 «цикл»; байты расширений
добавляют циклы, чтобы частота звука оставалась осмысленной.

### Базовые инструкции

* `NOP` — ничего.
* `SET a` — `grid[a] = 1`.
* `CLR a` — `grid[a] = 0`.
* `JMP a` — `pc = (pc & 0xFFC0) | a`. Используются только младшие 6 бит,
  поэтому прыжок не выходит за текущий 64-байтный блок. Это осознанное
  ограничение: блоки самодостаточны, поток управления прост.

### Расширения

`0xFC` зарезервирован как escape. SET/CLR/JMP кодируются только `0x40..0xFF`,
поэтому `0xFC` никогда не конфликтует. После `0xFC` следующий байт — подопкод:

| sub | операция | эффект                                              |
|-----|----------|-----------------------------------------------------|
| 0x00| `GET a`  | `acc = (grid[a>>3] >> (a&7)) & 1`                     |
| 0x01| `PUT a`  | установить/сбросить `grid[a]` из `acc`                |
| 0x02| `XOR a`  | `acc ^= бит GRID a`                                   |
| 0x03| `JZ a`   | если `acc == 0` — прыжок в пределах блока             |
| 0x04| `SETCH c p v` | установить параметр канала                      |
| 0x05| `JMPF a` | `pc = a` (полный 16-битный)                           |
| 0x06| `JZF a`  | если `acc == 0` — `pc = a`                            |
| 0x07| `COPY d s` | `grid[d] = rom[s]` (стриминг ROM в GRID)            |

`SETCH` пишет один параметр одного канала:

```
0xFC 0x04 канал параметр vL vH
параметр: 0=freq 1=duty 2=volume 3=mod_src 4=mod_depth 5=mod_dest
```

## Правило 64-байтного блока

GRID — 32 байта, значит младшие 6 бит любого адреса выбирают бит. JMP
использует текущий `pc & 0xFFC0` (содержащий блок из 64 байт) как старшие
биты — локальный прыжок. Программы длиннее 64 байт используют `JMPF`/`JZF`
(полные 16 бит). Директива `.org` размещает таблицы прошивки в любом месте ROM.

## Приёмы программирования

### Триггер / счётчик

«Вечная единица» (бит, который никто не сбрасывает) плюс `XOR` переворачивают
бит на каждом проходе:

```
SET  0x0F        ; вечная 1
GET  0x00        ; acc = bit0
XOR  0x0F        ; acc = bit0 ^ 1
PUT  0x00        ; bit0 = acc  → bit0 меняется каждый проход
JZF  CARRY       ; если bit0 стал 0 → перенос
JMPF DONE
```

Два бита дают 2-битный счётчик; `music.asm` использует его для прохода по
4-аккордной прогрессии (C–Am–F–G).

### Звук как состояние

Частота/скважность/громкость канала — обычные параметры, которые любой код
задаёт через `SETCH`. Свободно бегущий LFO — просто канал с низкой частотой,
модулирующий частоту другого канала (FM) или громкость (тремоло). Биты GRID
модулируют звук; звук модулирует звук.

## Звук

### Синтез квадратного сигнала

У каждого канала:

```
phase  : 16-битный аккумулятор (0..65535)
freq   : Гц (16 бит)
duty   : скважность 0..255
volume : 0..255
mod_src/mod_depth/mod_dest : модуляция
```

За каждый сэмпл (частота по умолчанию 44100 Гц, для 8086 — 22050):

```
phase += freq * 65536 / rate        (wrap на 65536)
sample = (phase < duty * 256) ? +1 : -1
out    = sample * volume / 255
```

### Модуляция

```
base   = freq или duty или volume (mod_dest)
src    = бит GRID (0/1) | выход канала (−1/+1) | выкл (0)
value  = base + src * mod_depth / 256
```

Модуляция применяется до формирования сэмпла; глубина — 8.8 фикс. точка
(256 = 1.0). Примеры: `MOD 0 0xF2 200 0` → частота ch0 модулируется квадратом
ch2 (покачивание ±200/256 Гц, т.е. FM); `MOD 1 0x10 120 2` → громкость ch1
управляется битом GRID 0x10 (флаг бита).

### Микширование

Три канала суммируются в `-3..+3`, ограничиваются до `-1..+1`, затем
масштабируются в знаковый 16-битный PCM. WAV — mono 16 бит.

## Отображение

Эмулятор печатает GRID как 16×16 с ANSI-цветами: зелёный `█` для установленного
бита, тёмный `░` для сброшенного. `--acc` также печатает регистры каналов.
`--steps N` выполняет N инструкций и печатает один кадр — удобно для отладки.

## Производительность и переносимость

* Ядро (`FluxCPU::tick`) без ветвлений, кроме прыжков; звук рендерится
  блоками, поэтому экспорт WAV быстрый.
* План порта на 8086: частота 22050 Гц, 16-битные целые, GRID как 32 байта,
  ROM из `firmware/*.flux`. См. SPEC.md — дорожная карта DOS.
