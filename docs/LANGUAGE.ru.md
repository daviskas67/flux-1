# Справочник языка ASM-Flux

ASM-Flux — язык ассемблера для однобитного компьютера ФЛЮКС-1. Программа
компилируется утилитой `asmflux` в сырой бинарный образ ПЗУ (`.flux`), который
загружает эмулятор.

```
usage: asmflux in.asm [-o out.flux] [-l list.txt]
```

## Синтаксис

* Одна инструкция на строку; `;` и `#` начинают комментарий (до конца строки).
* Числа: десятичные, либо с префиксом `0x`/`0b` (strtol base-0).
* Метки: `NAME:` — определяются по текущему адресу.
* Арифметика меток в операндах: `NAME+16`, `NAME-2` (с `COPY`, `.byte`,
  `.word`, прыжками).
* Мнемоники регистронезависимы.

## Базовые инструкции (1 байт)

| биты 7..6 | мнемоника | опкод   | значение                          |
|-----------|-----------|---------|------------------------------------|
| `00`      | `NOP`     | `0x00`  | нет операции                       |
| `01`      | `SET a`   | `0x40\|a` | grid[a] = 1                      |
| `10`      | `CLR a`   | `0x80\|a` | grid[a] = 0                      |
| `11`      | `JMP a`   | `0xC0\|a` | PC = (PC & 0xFFC0) \| a          |

`a` — 6 бит (0..63): SET/CLR адресуют GRID (0..255), JMP остаётся в пределах
текущего 64-байтного блока.

## Расширения (префикс 0xFC)

Байт `0xFC` никогда не выдаётся базовыми инструкциями, поэтому он работает как
escape-последовательность: `0xFC <sub> <операнды>`.

| мнемоника | sub | кодировка        | циклов* | значение                        |
|-----------|-----|------------------|---------|----------------------------------|
| `GET a`   | 0x00| `FC 00 a`        | +1      | ACC = grid[a]                    |
| `PUT a`   | 0x01| `FC 01 a`        | +1      | grid[a] = ACC                    |
| `XOR a`   | 0x02| `FC 02 a`        | +1      | ACC ^= grid[a]                   |
| `JZ a`    | 0x03| `FC 03 a`        | +1      | если ACC==0: прыжок в блоке      |
| `JMPF a`  | 0x05| `FC 05 aL aH`    | +2      | PC = a (16 бит)                  |
| `JZF a`   | 0x06| `FC 06 aL aH`    | +2      | если ACC==0: PC = a              |
| `COPY d s`| 0x07| `FC 07 d sL sH`  | +3      | grid[d] = ROM[s]                 |
| `SETCH c p v` | 0x04 | `FC 04 c p vL vH` | +2   | параметр канала c,p = v          |

\* дополнительные циклы сверх базового выборки/исполнения; важны для тайминга
звука.

## Звук (`SETCH c p v`)

Каналы `c` = 0,1,2. Параметры:

| p | параметр    | разряд  | значение                                       |
|---|--------------|---------|-------------------------------------------------|
| 0 | `freq`       | 16 бит  | частота в Гц                                    |
| 1 | `duty`       | 16 бит  | скважность (используются младшие 8 бит; 0 = тишина) |
| 2 | `volume`     | 16 бит  | 0..255 (младшие 8 бит)                          |
| 3 | `mod_src`    | 16 бит  | 0x00..0xFF бит GRID, 0xF0..0xF2 канал, 0xFF выкл |
| 4 | `mod_depth`  | 16 бит  | 8.8 фикс. точка (256 = 1.0, знаковое)           |
| 5 | `mod_dest`   | 16 бит  | 0=freq 1=duty 2=volume                           |

Сахар ассемблера:

```
FREQ ch v
DUTY ch v
VOL  ch v
MOD  ch src depth dest     ; раскрывается в 3 инструкции SETCH (18 байт)
```

### Алгоритм модуляции

Для каждого сэмпла и канала:

```
base   = freq (или duty, или volume) канала в зависимости от mod_dest
src    = значение бита GRID (0/1), или выход канала (+1/−1), или 0, если выкл
target = base + src * mod_depth / 256
```

* `mod_src` в `0x00..0xFF`: читает бит GRID. Глубина 256 × бит 1 = +1.0.
* `mod_src` в `0xF0..0xF2`: источник — квадратный выход этого канала (−1/+1).
  Отрицательная глубина инвертирует. Так получаются FM (dest=freq), модуляция
  скважности (dest=duty), тремоло (dest=volume).
* `mod_src = 0xFF`: модуляция выключена.

### Квадратный сигнал

У каждого канала 16-битный фазовый аккумулятор, шаг за сэмпл:

```
phase += freq * 65536 / sample_rate      (по модулю 65536)
sample = (phase < duty * 256) ? +1 : -1   (duty в 0..255)
```

Каналы суммируются и ограничиваются до 16-битного PCM (`-1.0..+1.0 →
-32767..+32767`).

## Директивы

| директива        | значение                                      |
|------------------|------------------------------------------------|
| `.org N`         | продолжить сборку с адреса N                    |
| `.byte v,...`    | эмитить байты (через запятую, арифметика меток) |
| `.word v,...`    | эмитить 16-битные слова, little-endian          |
| `.incbin "file"` | включить сырой бинарный файл                    |
| `;` / `#`        | комментарий до конца строки                     |

## Примеры

Бегущий огонёк:

```asm
START:
    SET  0x00
    CLR  0x01
    JMP  START          ; 64-байтный блок, цикл навсегда
```

Триггер-«счётчик» через вечную единицу в 0x0F:

```asm
    SET  0x0F           ; вечная 1
    GET  0x00
    XOR  0x0F           ; ACC = bit0 ^ 1  (инверсия)
    PUT  0x00           ; bit0 перевернулся
    JZF  CARRY          ; если новый bit0==0 — был перенос
    JMPF DONE
CARRY:
    GET  0x01
    XOR  0x0F
    PUT  0x01
DONE:
```

Стриминг кадра ROM в GRID (в стиле анимации):

```asm
    COPY 0  FRAME+0     ; байт GRID[0] = ROM[FRAME]
    COPY 1  FRAME+1
    ...
FRAME:
    .byte 0x0F, 0xF0, ...
```

## Примечания

* `0xFC` не может быть записан как данные инструкциями SET/CLR (адреса ≤ 0xFF,
  но SET/CLR кодируются `0x40..0x7F`/`0x80..0xBF`); при необходимости
  используйте `.byte 0xFC` в данных — CPU декодирует его как расширение.
* Блоки: `JMP`/`JZ` по замыслу ограничены текущим 64-байтным блоком; для
  прыжков в любое место используйте `JMPF`/`JZF` (4 байта).
